## 补充修复

| 问题 | 触发与影响 |
| --- | --- |
| 部分配置导入覆盖失败输入 | API Key 保存失败，界面承诺保留输入；再导入只含 prompt 的备份，无条件重载表单会将新 Key 抹掉。 |
| 导入和连接测试争用按钮状态 | 连接测试进行中启动导入；测试先结束会在导入期间启用按钮，导入结束又恢复过期的 disabled 快照，使按钮永久禁用。 |
| 迟到保存回执回退历史缓存 | A 保存后回执延迟，B 保存更新正文；A 已接收新存储事件，却又用旧回执覆盖本地缓存，重新打开仍显示旧正文。同类译文回执也会回退缓存，导致搜索不到较新译文。 |
| 外部删除后语言切换隐藏编辑 | 一处编辑正文和名称，另一窗口删除记录；切换语言直接回到列表，未保存输入随下次打开记录被覆盖。 |
| 跨窗口外观未同步 | 语言运行时已收到新值，但设置／Popup 没有更新选择器及标签；设置页主题也不跟随其他窗口。语言通知晚于导入完成时同样出现。还补查并修复了既有的初始化竞态：首次读取或加载字典期间，尚未绑定监听器会漏掉另一窗口的语言变更。 |

以上问题均在修复前独立复现，严重度为 P2。本次不扩大到批量、表格或离线功能。

修复后的行为：

- 部分导入只替换明确提供的字段，省略的未保存输入继续显示并保留警告，可重试保存；显式导入该字段时清除旧错误。新字段状态会取消旧的提示清理定时器。
- 连接测试按钮由导入、连接测试两个进行中状态共同决定，任意完成顺序都不会提前解锁或永久禁用。
- 正文保存响应通过字段版本检查更新缓存；译文缓存由存储事件更新，删除旧回执的重复覆盖。
- 语言切换只刷新当前界面的标签与元信息，保留正文、名称、草稿和翻译会话；外部删除的记录仍可复制本地输入，并显示记录缺失提示。
- 设置和 Popup 订阅外观变化；语言初始化先绑定监听，首次读取的迟到成功或失败均不能覆盖较新的通知。内容脚本仍通过消息读取偏好，不直接访问受限存储。

新增 4 项语言运行时单元测试、9 项 Chromium 回归，覆盖以上复现、两种异步完成顺序、错误重试、显式替换和会话保留。新增浏览器场景位于 `options-settings.spec.js`、`review-history-save.spec.js`、`appearance-settings.spec.js`。
