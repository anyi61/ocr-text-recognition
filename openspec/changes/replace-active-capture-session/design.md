## Context

动机见 `proposal.md`。现有 `content.js` 使用闭包中的 `captureSessionId`、`activeRequestId`、`isCapturing`、`isProcessing` 管理一次操作。`startCapture()` 忙碌时直接返回；`captureAndRecognize()` 的成功路径已有多处身份校验，但 catch 在检查身份前关闭进度。`confirmSelection()` 在等待上传告知之后才读取当前会话 ID，旧流程可能误用新会话状态。

上传告知内部 Promise 通过局部 `finish()` 结束，目前外部清理无法主动结算它。后台已支持按 requestId 取消及取消期间历史写入补偿。现有测试包括真实后台消息契约、Mock Chromium 场景，以及记录忙碌时忽略再次启动的现状测试。

## Goals / Non-Goals

**Goals:** 以最小运行代码改动实现同标签页会话替换，覆盖所有异步阶段并提供确定性的竞态测试，为后续模块拆分建立可靠行为基线。

**Non-Goals:** 本轮不拆目录、不新增全局队列、消息协议或持久化字段；不改变服务商选择、告知版本和历史保留规则；不承诺撤回服务商已经接收的数据。

## Decisions

### 1. 在现有闭包内统一结束会话

增加局部结束操作，供再次启动、主动取消及页面卸载复用：先保存旧请求标识并使旧会话失效，再清理旧选区、监听、告知和进度，最后按旧 requestId 发送 `cancelOCR`。调用幂等，局部清理不移除仍需使用的 runtime 监听或破坏新会话；页面卸载再执行完整销毁。

随后生成新会话 ID 并建立空白选区。请求取消采用原消息通道，不等待网络取消完成才展示新框选；取消消息失败时仍保持本地旧会话失效，不让拒绝的 Promise 污染新 UI。相比等待服务商响应或完整重注入，此方式复用现有通信与加载边界。

会话范围保持每标签页独立。重复注入初始化仍幂等；每个有效的 `startCapture` 用户启动消息创建新会话，连续启动由最后一次生效。

### 2. 所有异步路径携带起始会话身份

`confirmSelection()` 在首次 await 之前捕获会话 ID 和选区快照；告知、截图、裁剪、识别每次 await 后均验证仍属于当前会话。catch 和 finally 同样受身份约束，不能只保护成功路径。旧异常不隐藏新进度、不显示旧错误；旧 finally 仅释放其仍拥有的状态。

普通通知计时器、告知回调及其他会话相关资源也需要检查所属对象/身份，避免旧定时清理删除新对象。主题/语言的共享偏好读取继续沿用现有语义，不新增会话持久化。

### 3. 告知弹窗可结束，保留用户真实同意

为当前会话保留告知关闭/结算句柄。结束会话时以未同意结算尚待用户操作的告知，移除其 DOM 与监听，并让原确认流程自然退出；旧句柄不能修改新会话的 `uploadNoticeOpen`。

用户已经明确同意且告知版本写入已经开始时，不回滚其真实同意；但旧流程即使收到成功写入响应也不得上传旧选区。仅替换会话本身不算同意。该约定保留既有一次性告知政策。

### 4. 历史复用现有取消契约

取消及时到达仍运行的请求时，复用后台 AbortController、写前检查与写入补偿，不留下被取消请求的新增历史。取消到达前已经完成并提交的记录属于已完成识别，保留原有历史，不实施追溯删除。旧结果无论是否已经写入历史，都不能覆盖新会话 UI。测试用受控延迟明确区分“仍运行时取消”和“已完成后回调迟到”。

### 5. 通过确定性时序验证行为

- 将 busy restart 现状测试改为验收：延迟旧请求 → 再次启动 → 服务端观察旧连接取消 → 新选区确认 → 仅新请求完成并写入历史。
- 覆盖框选/告知中替换、截图/裁剪等待时替换、快速取消再启动、A/B 标签页隔离。
- 网络连接被中止不能证明迟到回调隔离。测试单独控制旧成功、失败和告知 Promise 的释放顺序，断言新 UI 与新请求仍有效。可使用测试副本中的消息桥接或可控 VM/DOM harness，不给生产代码增加公开调试接口，不解除可信事件限制。
- 变异验证仅改临时测试副本：移除会话身份保护后，对应迟到响应测试必须失败；记录原版通过、变异版失败的证据，工作区源码不带变异。

## Risks / Trade-offs

- [单一布尔取消标识被新会话重置] → 每个回调同时验证会话身份，不能只依赖 `isCancelled`。
- [旧告知 Promise 挂起或错误路径影响新 UI] → 主动结算旧告知、完整保护 catch/finally，并覆盖成功与拒绝两种迟到路径。
- [取消与历史提交竞态] → 保留已完成记录，明确测试取消发生在提交前的场景；不扩大为新历史事务系统。
- [测试误把 HTTP 取消等同于会话安全] → 另测可控迟到响应和变异失败；不得以固定等待时间作为唯一时序证据。

## Migration Plan

先写新行为测试并记录旧实现失败，再在现有 `content.js` 修正生命周期。针对性测试通过后运行完整 `npm run check`、`npm run package` 与 OpenSpec 严格校验，记录到本变更 `verification.md`。

本变更实施并验收后，按 sync/archive 流程同步 `capture-session` 主规格；原 `modularize-ocr-extension` 继续保持纯重构，复用此证据完成其任务 1.4，再重新确认阶段 1 门禁。该交接不能凭测试数量自动勾选，需核对原任务包含的全部场景及变异验证。

回退仅恢复本变更审阅过的业务文件与对应测试，保留之前的检查隔离和消息契约成果；无需回退存储数据或修改用户配置。
